# warehouse-video-script-skill

把电商仓储专业知识写成老板和仓库负责人愿意继续看的中文短视频口播。

本仓库将既有的短视频口播 `agent.md` 转换为可复用的 **Codex Skill**，技能名称为 **`warehouse-video-script`**。它保留原有写作框架：**滑梯效应、4–7层问题链、每5–10秒的信息回报，以及经营价值和自然行动引导**。

默认支持 **60–90秒中文口播**，也可指定目标受众、时长、平台和风格。它生成文案，不负责视频剪辑、配音、渲染或发布。

## 主要功能

- 从一个仓储标题、业务问题或已有草稿开始写作。
- 把知识目录改成观众的问题，让专业概念作为答案自然出现。
- 按“痛点 → 反常识 → 真正原因 → 新问题 → 专业方法 → 风险／补充变量 → 经营结论 → 行动引导”推进。
- 给出完整正文和覆盖全稿的滑梯节点，检查每5–10秒是否有真实信息回报。
- 保留仓储咨询的专业判断与商业价值，避免培训腔、强制营销和空悬念。
- 不虚构数据、客户案例、个人经历或结果承诺；无依据时采用有条件的机制解释和诊断动作。

## 适用人群

电商仓储咨询从业者、仓储服务商内容团队、电商老板、仓库负责人，以及需要把库存、人效、差错、退货、布局和流程知识转成短视频口播的创作者。

## 安装到 Codex

此仓库只包含文本技能，无需配置 API Key、数据库或安装业务依赖。

下载本仓库 ZIP 并解压，或克隆公开仓库：

```sh
git clone https://github.com/yuew2841-spec/warehouse-video-script-skill.git
cd warehouse-video-script-skill
```

在仓库根目录，将 **技能文件夹** 安装到个人技能目录：

```sh
mkdir -p ~/.codex/skills
cp -R skills/warehouse-video-script ~/.codex/skills/
```

如果目标目录已有同名技能，先比较内容再更新，避免直接覆盖自己的修改。上面是常见的个人目录安装方式；如果你的 Codex 配置了其他技能目录，将同一个文件夹复制到对应位置即可。不要把整个 GitHub 仓库当成一个技能文件夹。

重新打开 Codex 会话后，可用 `$warehouse-video-script` 显式调用。支持自动发现时，匹配“写仓储口播”等请求也可触发；自动选择结果取决于当前客户端。

## 使用方法

只给一个主题即可：

```text
请用 $warehouse-video-script 写一条口播：仓库人效低第一步怎么做。
```

也可以明确参数：

```text
请用 $warehouse-video-script 写口播。
主题：纯计件薪酬能否降本增效
目标受众：电商老板
目标时长：约75秒
平台：视频号
内容风格：专业清晰、有经营判断
事实资料：未提供真实经营数据或客户案例，请不要编造。
```

可选字段包括 `audience`、`duration_seconds`、`platform`、`style`、`facts`、`draft` 和 `output_mode`，不必写成 JSON。用户说“只要文案”时，仅输出正文，问题链和质量自检在内部完成。

## 输入输出示例

以上述纯计件选题为例，默认输出以下五部分：

**口播标题**：纯计件，不等于效率不重要

**核心问题链（节选）**：纯计件还需要提效吗？→ 单价固定不等于每单总耗时固定 → 时间浪费在哪里？→ 找货、补货和等待可能压低日完成量 → 直接压单价能解决吗？

**完整口播（节选）**：

> 纯计件，效率就不重要了？
>
> 单价一样，发得快慢都要付这些钱。这个判断漏了一件事：每单背后耗了多少工时。
>
> 同样一批订单，找货、补货、等复核的时间越长，员工一天能完成的订单就越少。

**滑梯节点（节选）**：

| 规划时间 | 新信息回报 | 接出的下一问 |
| --- | --- | --- |
| 0–3秒 | 抛出计件与效率的冲突 | 固定单价为什么还要提效？ |
| 3–11秒 | 区分计件单价和总工时 | 工时耗在什么地方？ |
| 11–19秒 | 指出等待与日完成量的关系 | 那直接降单价呢？ |

**可选封面标题**：纯计件，也要算效率账；别把压单价当成提效；企业与员工怎样一起受益。

这里展示的是节选，完整输入、正文与时间规划见 [纯计件薪酬样稿](examples/01-piece-rate.md)。规划秒数不是实测配音结果，需要按实际语速和停顿试读校准。
